# 酒馆回话格式规范（TRS —— Tavern Reply Syntax v1）

> 这份文档是**唯一权威语法定义**。插件按它解析，预设按它约束模型。
> 改语法先改这里，再同步 `lib/parse.js` 和预设里的约束段。

## 为什么需要它

模型每次说的话是随机的：同一张卡，今天输出 `<Status>好感72</Status>`，明天可能
输出 `<状态>好感:72</状态>`，后天干脆一段散文。位置式写法（`62|18|心声|穿着|…`）
尤其危险 —— 字段顺序全靠模型自觉，换个模型就错位。

所以这里规定**带名字的语法**：每个值都自己说明自己是什么，顺序无关、可缺省、
可增删。解析器永远知道自己在读什么。

## 铁律

1. **整个回复必须包在 `<scene>` 里**，没有例外。
2. **只用本文档列出的标签**。不要自创、不要改名、不要嵌套 `scene`。
3. **标签必须闭合**，小写。
4. **交互正文只写在 `<prose>` 里**；`<panel>` 只放状态与信息。
5. **属性用命名式**：`affection=72`，不要 `72|18|` 这种位置式。
6. **拿不准的字段就不要写**。少写一格比写错位置好得多。

## 骨架

```
<scene>
<prose>
（正文：旁白 + 对话）
</prose>
<panel>
（可选：状态 / 消息 / 动态 / 推荐 / 选项，顺序随意，缺省随意）
</panel>
</scene>
```

`<panel>` 整块可省。`<prose>` 必写。

---

## 一、正文 `<prose>`

正文里用**三种标记**区分信息类型，这是观感的全部来源：

| 类型 | 写法 | 会被渲染成 |
|---|---|---|
| 旁白 | 普通文字 | 常规字号、常规色 |
| 对话 | `"双引号包起来"` | 放大、衬线字体、青色、左侧竖线 |
| 神态/动作 | `*星号包起来*` | 斜体、小一号、淡紫、浅底 |

示例：

```
<prose>
晨光从露台的玻璃门斜切进来，在地毯上划出一道浅金色的边。
"爸爸，早……啊❤"她把铲子放下，转过身来，*耳朵先红了*。
"清韵做了早饭。那个……蛋有点焦，对不起。"
</prose>
```

要点：

- **说话内容必须进引号**，不要裸写对白。这是「交谈」和「介绍」的唯一区分方式。
- 引号内不要再嵌引号；要引用别的话用「」。
- 神态、小动作、心理活动用星号；**不要**用星号表示强调或书名。
- 旁白里不要塞大段设定说明 —— 设置定放 `<panel>` 的 `<info>`。

## 二、状态 `<status>` —— 最重要的一块

每个角色一个 `<char name="名字">`，里面用**命名属性**描述状态。

```
<status>
  <char name="清韵" affection=62 reason=18 mood="紧张又期待" outfit="米色棉布长裙，外系浅棕围裙，赤足棉拖" body="隔着布料微微发烫">
    心声：爸爸在看这边……明明只是做早饭。
  </char>
  <char name="昕彤" affection=75 reason=12 mood="黏人撒娇" outfit="宽大白衬衫当裙子，只扣两颗扣子，赤脚">
    心声：爸爸的手好暖哦。
  </char>
</status>
```

### `<char>` 的可用属性

| 属性 | 含义 | 建议取值 |
|---|---|---|
| `name` | 角色名（**必填**） | 文本 |
| `affection` | 好感度 | `0`–`100` 整数 → 渲染成圆环仪表 |
| `reason` | 理性 / 理智 | `0`–`100` 整数 → 圆环仪表 |
| `mood` | 当前心情 | 短词，会渲染成彩色标签 |
| `outfit` | 穿着 | 一句话 |
| `body` | 身体感受 | 一句话 |
| `place` | 所在位置 | 短词 |
| `flag` | 状态标记 | 短词，如 `醉酒` `受伤` |
| 其他任意属性 | 自定义 | 自动归为「标签」或「说明」，不会丢 |

- **数值一律写属性，不要写位置**。`affection=62`，不是 `62|18|`。
- 属性值含空格时加引号：`mood="紧张又期待"`。
- 任意属性都会被显示；**没定义的属性也不会报错**，所以你想加 `stamina=40`
  也可以，解析器会按「数值 → 仪表 / 短词 → 标签 / 长句 → 说明」自动归类。
- `<char>` 里星号外的文字当作「心声」，单独排版。

## 三、其他面板区块（都可以只用一部分）

### 消息流 `<chat>`

```
<chat time="07:20">
  <msg from="昕彤">爸爸起床了哦！快下来快下来！</msg>
  <msg from="清韵">……蛋要凉了呢</msg>
</chat>
```

### 动态 / 社交媒体 `<feed>`

```
<feed source="推特">
  <post name="养女日常" handle="Petropavlovsk" stats="43k">
    周六早上！爸爸还在睡，彤彤已经做完早饭了哦（其实是姐姐做的）
    <note>图片：吧台上的煎蛋.jpg —— 两颗略微焦边的煎蛋，旁边是两只小手比着V。</note>
  </post>
</feed>
```

### 推荐 / 列表 `<list>`

```
<list title="推荐">
  <item>周六限时：家用手冲咖啡套装，买一送一</item>
  <item>真空睡裙新款上架，薄如蝉翼</item>
</list>
```

### 选项 `<choice>`

```
<choice>
  <opt>先喝月绮递来的牛奶，再坐下吃早饭</opt>
  <opt>把昕彤抱上吧台</opt>
  <opt>让清韵把围裙解下来</opt>
</choice>
```

### 场景信息 `<info>`

```
<info time="07:22 周六" place="家中厨房" weather="晴" />
```

用于时间、地点、天气这类元信息。

## 四、必须避免

| 不要 | 因为 |
|---|---|
| `<Status>` `<phone>` `<mainbody>` 老格式 | 仍能兼容解析，但新回复一律用新语法 |
| `62\|18\|心声\|穿着\|…` 位置式 | 字段顺序失控，换模型就错位 |
| 自创标签如 `<心情>` `<状态>` | 解析器不认识，会当普通文字 |
| 标签不闭合 / 大写 | 解析失败 |
| 正文里裸写对白 | 无法和旁白区分 |
| 把大段设定塞进旁白 | 该进 `<info>` 或卡面 |

## 五、给模型的最小示范（一段完整回话）

```
<scene>
<prose>
晨光从露台的玻璃门斜切进来。你还没完全睁开眼，楼下的动静就顺着楼梯爬了上来。
"爸爸，早……啊❤"清韵把铲子放下，转过身来，*两只手在围裙上蹭了两下*。
"清韵做了早饭。那个……蛋有点焦，对不起。"
</prose>
<panel>
<status>
  <char name="清韵" affection=62 reason=18 mood="紧张又期待" outfit="米色棉布长裙，浅棕围裙，赤足棉拖" body="微微发烫">
    心声：爸爸在看这边……明明只是做早饭。
  </char>
</status>
<choice>
  <opt>坐下吃早饭</opt>
  <opt>先看看清韵的围裙怎么了</opt>
</choice>
</panel>
</scene>
```

## 兼容说明

老格式（`<mainbody>` / `<phone>` / `<Status>` + 位置式）插件**仍然能读**，
用来兼容网上现成的酒馆预设。但那只是兜底：字段顺序靠猜，显示效果不如新语法稳定。
新写的预设请一律用本文档的命名式语法。
