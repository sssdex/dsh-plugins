# 解题·推导 · fast-solver（DSH agent 预设）

专做「文字 / 截图 + 有标准答案 + 1–5 步推导」的理科计算题。
输出 = **能复算的推导 + 单独一行准确答案**。不套模板、不注水、不寒暄。

需求经 2026-11-07 四轮访谈定稿，优先级 **准确度 > 可看懂怎么算出来的 > 不啰嗦**，准确度一票否决。

## 文件

| 文件 | 作用 |
| --- | --- |
| `package.json` | DSH bundle 声明（指向 `cordis.patch.yml`） |
| `cordis.patch.yml` | 核心：一条 `@deepseek-ai/dsh-agent-preset` 声明，用 `- insert:` 注入 |
| `README.md` | 本说明 |

安装：`plugin_manager install_bundle`，`target` = 本目录绝对路径。改完声明需 `remove_bundle` → `install_bundle`（同名覆盖会报 `already-installed`）。

> ⚠️ 旧格式 `$DSH_HOME/.agent-presets/<id>/`（`preset.yml` + `agent.cordis.yml`）已废弃，当前 DSH 不再读取。本 bundle 用现行「声明行」机制，与内置 `standard`/`minimal` 一致。

## 版本演进与定稿理由

| 版本 | 做法 | 反馈 |
|---|---|---|
| v1 只给答案 | 只输出最终结果 | 快且准，但「没过程没用」 |
| v2 四段式 | 强制 思路/过程/讲解/答案 + 讲解段 | 长、死板、注水、把题算错 ——「没之前好了」 |
| v3 减负 | 恢复紧凑、允许写推导 | 方向对，但目标函数错（仍把「快」当主目标） |
| **v4（定稿）** | 准确度第一 + 可复算推导 + 单独答案行 | 本版 |

访谈里关键的一句硬约束是「**不能准确度下降**」。这重排了整个目标：四段式被否的核心罪状是算错，不是长；「只给答案版」显得好，是因为它干脆、不分心、算得准。所以定稿把准确度摆第一，**允许为了算对多写一步、略长略慢**，绝不为短/快省推导或凑格式。「快」不再单列指标，只是「不写废话」的副产品。

## 具体形态（Q10/Q14）

- 一段连贯正文，**每步一行**关键算式 / 公式 / 单位 / 依据，不跳步
- 步数按难度自适应 **1–5 步**，一步能说清就别拆
- **无任何小标题、不分四段**；「为什么」只在真有助于看懂时顺带一句，不专门写讲解段、不列易错点、不总结拓展
- **最后单独一行**给明确答案：选择题「字母. 选项内容」，计算 / 填空给最终结果
- 多题按 `1./2./3.` 逐题作答
- 不寒暄、不复述题目、不描述整张图、不注水、不重复结论、不「验证一下」再抄一遍、不自我检查
- 中文作答（题目为英文或明确要求英文时随题）；截图看不清 / 缺条件 / 歧义时一句话说明缺什么

## 边界

- **零工具**：不联网、不跑代码、不读文件。需要查资料 / 复杂数值验算 / 读 PDF 的题切回 **standard**。
- 保持 `complete: true`（阻止上层 listener 追加长文本、缩短 prefill）+ `includeRuntimeContext: false`（去掉每轮运行上下文快照）。砍的是废话与格式负担，不是必要步骤。
- **图片**：用户直接贴的截图是 user message 的 `ImageBlock`，由 Host 附件服务注入，`complete` / `includeRuntimeContext` 不碰消息内容块；唯一硬条件是模型支持图片输入（本机 hy4free 满足）。零工具的代价是不能主动 `read_image` 读磁盘路径上的图。
- **本次范围只改预设 prompt**：预设改不了模型、也关不了思考（那是 `/model` 和模型目录的事），换模型 / 调推理深度另议。

## 验收流程（Q13/Q15，前三轮翻车的直接原因）

1. 改 prompt → `remove_bundle` + `install_bundle` → `list_plugins` 确认 `include:preset-fast-solver` **active 且无 diagnostic**
2. 在**新建空白会话**里用 2 道文字题实测（附手算标准答案）：
   - ① 一步出结果的简单题 —— 看会不会硬凑格式、写废话
   - ② 3–5 步带公式的题 —— 看多步会不会算错
3. **原样贴出模型原始输出**，由用户按「准 / 看得懂 / 啰不啰嗦」判；不过就回来继续调，直到通过
4. 若程序化「新建会话 + 指定预设 + 取回输出」在本机走不通，须**明说做不到**、改为用户手动跑，绝不假装测过

## 注册与选择

id `fast-solver`、order `7` 不变；名字「解题·推导」，**不设默认**（默认仍是 standard）。只在**空白会话**（还没开始第一轮）的下拉框里能选；已开始的会话保留原预设。

## 调校提示

- 推导偏长 → 在 `prefix` 加「推导默认 2–4 步，难题才展开」（注意别违反准确度优先）
- 多题连发 → 已有 `1./2./3.` 规则
- 改完声明后需 remove + install，并在**新会话**生效。
